# 3D LUT 拟合：原理与优化空间

本文说明 `lutfit` 是怎么工作的，以及**为什么它在某些数据上已经到顶、在另一些上还有空间**。
所有数字都是本项目实测，不是估计。

---

## 1. 问题定义

给定 N 对图：A 是相机原图，B 是修图师修完的成品。要产出一个 3D LUT，
把任意照片从 A 的色彩风格映射到 B 的。

关键约束：**只有一个 LUT，且它只能依赖颜色**——不能依赖像素位置、不能依赖图像内容。
这个约束决定了后面所有的天花板。

---

## 2. 为什么 3D LUT 能拟合任意色彩变换

### 2.1 关键洞察：插值对格点值线性

色彩变换本质是 `R³ → R³` 的映射。修图包含色相偏移、局部饱和调整、高光滚降，
这些都是非线性的，没法用一个矩阵表示。

3D LUT 的做法：在色彩立方体上撒 `n³` 个格点，每点存一个输出 RGB，查询时插值。

**四面体插值**是这样工作的：给定输入 `u`，先判断它落在哪个小四面体里，
然后输出是四个角的加权和。

> **落在哪个四面体，只取决于 `u` 的位置，跟格点里存的值完全无关。**

于是可以写成：

```
输出 = T(u) · x
```

- `x` = 全部格点值拼成的向量。33³ 时是 `3 × 35937 = 107811` 维
- `T(u)` = `3 × 107811` 的稀疏矩阵，每行只有 **4 个非零**（四个角的权重）

**这一步把"拟合非线性色彩变换"变成了线性最小二乘问题。**
整个方法的地基就是这一句。

### 2.2 从像素到方程组

几亿像素不可能逐像素建方程。按色彩空间分箱（默认 65³）：

- 每箱内 A 的码值取平均 → `a_i`
- B 的码值取平均 → `b_i`
- 权重 `w_i` = 箱内像素数

目标：

```
min Σ w_i ‖T(a_i)·x − b_i‖²
```

---

## 3. 数据管线

### 3.1 掩膜

`build_mask` 排除三类像素：A 或 B 接近裁剪（`>0.98` 或 `<0.015`）、
以及梯度大的像素（A 和 B 中任一梯度超过 90 分位，再膨胀 1 圈）。

理由：裁剪像素没有信息；边缘像素要么是运动/错配，要么修图处理方式与平坦区不同。

### 3.2 中性轴

从低彩度像素（`chroma < 0.02`）估计一条灰阶映射曲线，作为先验。
作用是防止 LUT 给中性色引入色偏。可用「保持灰阶中性」开关关闭。

---

## 4. 求解

### 4.1 为什么不能直接解

`TᵀWT` 是 `107811 × 107811`。存稠密矩阵需要 **93 GB**。

但 `T` 是稀疏的（每行 4 个非零），所以**根本不需要构造这个矩阵**，
只需要能算两个操作：

```
y = T·x        正向：给定 LUT 算输出
g = Tᵀ·(w·r)   反向：把残差散射回格点
```

### 4.2 预条件共轭梯度

有了上面两个操作就能用 PCG 迭代求解。预条件子用 `TᵀWT` 的对角线（Jacobi）。

实测（数据集2，33³）：**45,963 次 matvec，平均 1.68 ms/次**，拟合阶段共 77 秒。

### 4.3 箱约束

LUT 值必须在 `[0,1]`。**不能在解完之后裁剪**——裁剪会破坏已经解好的平衡
（一个格点被拉回 1.0，周围格点却没有相应补偿）。

正确做法是求解过程中就约束：原对偶活跃集法，每轮找出顶到边界的变量固定住，
只解剩下的自由变量。这样其余格点能在求解时主动补偿。

---

## 5. 正则化

没有正则化，解会烂掉。三个原因：

1. **没数据的地方**：数据集1 只有 31.4% 的格点有足够数据，其余是纯外推
2. **病态**：相邻格点高度相关，解不唯一
3. **伪影**：解出来会有色彩反转和色带

四个惩罚项：

| 项 | 形式 | 作用 |
|---|---|---|
| 平滑 | `λ·‖Lx‖²` | 拉普拉斯，惩罚二阶差分 |
| 先验 | `β·‖x − x_ref‖²` | 向上一层粗解靠拢 |
| 中性轴 | `γ·‖x − g‖²` | 灰阶映射到灰阶 |
| 单调 | `μ·(雅可比对角线下界)` | 防止局部斜率变负，IRLS 加权 |

系数做了无量纲归一化（相对 `d₀/W`），能对齐数据**量**，但对不齐变换**强度**。

> ⚠️ 早期版本曾声称「换数据集不用调参」，**这个说法在第二批数据上被证伪**。
> 现在改用自适应搜索（见 §8）。

---

## 6. 多尺度

不直接解 33³，而是 `5³ → 9³ → 17³ → 25³ → 33³` 逐层解：

- 5³ 只有 125 个未知数，几乎不会病态，解出来的是"大局"（整体影调、色偏方向）
- 把它的输出**上采样**当作下一层的先验 `x_ref`
- 每层在前一层基础上精修

效果是收敛更快、更稳定。

---

## 7. 后处理：伪影治理

### 7.1 色域压缩

超出 `[0,1]` 的值按 **Oklab 降彩度**处理，不是硬裁剪。
硬裁剪会产生色相偏移（饱和青色被裁成灰色）。

### 7.2 单调投影

用 PAVA 保序回归强制雅可比对角线为正（沿 R 增加，输出 R 不能减少）。

### 7.3 折叠修复

`det(J) ≤ 0` 的胞元是**局部色彩反转**——这是形式化的"色彩折叠"定义
（不是"看起来有带"）。对这些胞元做局部平滑。

### 7.4 一个踩过的坑：修复与投影互相打架

- 折叠修复会破坏单调性
- 单调投影会制造新的折叠

先后各跑一次等于回到起点（实测：修完 0 折叠，投影后又变 155 个）。

**正确做法是交替执行、每轮用统一指标打分、保留联合最优。** 见 `polish_lut()`。

---

## 8. 自适应正则化

末层解完后检查折叠数，没清零就把 `λ` 和 `μ` 同时加倍重试（最多 3 次），
加强没有改善就早停。

实测：**两批数据都在第一次尝试就零折叠**，这个循环目前只是安全网。

---

## 9. 误差账本

### 9.1 分解恒等式

```
总误差² = 模型误差² + 不可约下界²
```

**模型误差**：LUT 输出与箱均值的距离，是拟合算法能改进的部分。

**不可约下界**：箱内 B 的方差。同一个输入颜色，修图结果不一致。
任何只依赖颜色的映射都消不掉它。

实测：

| | 模型误差 | 下界 | 总 | 总/下界 |
|---|---|---|---|---|
| 数据集1（46 组，温和调色） | 0.01299 | 0.02692 | 0.02989 | +11.0% |
| 数据集2（87 组，强风格化） | 0.03893 | 0.07357 | 0.08324 | +13.1% |

模型误差在平方误差里只占 **18.5%**。

### 9.2 下界分解：图内 vs 图间

下界本身还能再分。令 `r = B − b̄(bin(A))`，利用方差分解恒等式：

```
Var(r) = E_j[Var_j(r)] + Var_j[E_j(r)]
       =     图内     +     图间
```

（交叉项为零，因为每张图的残差均值就是它自己的均值。）

- **图内差异**：同一张照片里的局部调整（渐变蒙版、画笔）。
  **全局 LUT 原理上救不了。**
- **图间差异**：不同照片修法不一致。**理论上可用多个 LUT 消掉。**

只需为每张图存 3 个累加量，不需要按 (箱, 图) 存储。

实测：

| | 图内差异 | 图间差异 |
|---|---|---|
| 数据集1 | **68.3%** | 31.7% |
| 数据集2 | 39.3% | **60.7%** |

恒等式在浮点精度内成立（偏差 6e-17）。

## 10. 优化空间分析

### 10.1 天花板

| | 完美拟合（模型误差→0） | 完美聚类（图间差异→0） |
|---|---|---|
| 数据集1 | 降 **9.9%** | 降 **13.8%** |
| 数据集2 | 降 **11.6%** | 降 **27.5%** |

**结论：**

- **数据集1：算法到顶了。** 68.3% 的下界来自图内局部调整，任何全局色彩映射都碰不到。
  剩下能动的加起来也就 13.8%（还是上界）。
- **数据集2：有实质空间，但不在拟合，在聚类。** 聚类是拟合的 2.4 倍。

### 10.2 已排除的方向

| 方向 | 为什么排除 |
|---|---|
| **提高分辨率** | 实测 9³ +22.7% → 17³ +12.8% → 33³ +11.9% → 49³ +10.2%。从 17³ 到 49³ 只买到 2.6 个点，且 49³ 有无法修复的折叠 |
| **加强正则化** | ΔE 对 λ 完全不敏感（λ 从 6 到 80，ΔE 3.80 → 3.81） |
| **上 GPU** | 45k 次**串行**的小矩阵向量乘，每次仅 116 万 FLOP。M 系列 GPU 纯算力约 30ms 能算完，但每次迭代要 6 个左右 kernel dispatch，光派发就要 5-27 秒。数据局部性上解向量 864KB、算子 4MB 完全装得进 CPU 缓存。**不划算。** |

### 10.3 K-LUT（多个 LUT）

**K-LUT = K 个 LUT。** `K` 借自聚类算法的写法，K=3 就是分成 3 组、输出 3 个 `.cube`。

**动机**：现在 87 组图 → 1 个 LUT，必须对不同的修图风格取折中。
按风格分组后各拟合一个，每个只需管好自己那一类。

**为什么和下界分解直接相关**：图间差异就是 K-LUT 能治的病。
60.7%（数据集2）意味着误差里有六成是"照片之间风格不一致"造成的。

**致命问题：新照片用哪个 LUT？**

| 方案 | 问题 |
|---|---|
| 修图师自己选 | 要人判断，那还不如他直接调 |
| 按新照片色调自动匹配 | 会匹配错，错了比不分组还糟 |
| 再输出一个"平均" LUT 兜底 | 分组的意义只剩一半 |

**这个问题不解决，K-LUT 不是功能，只是实验。**

另外注意：27.5% / 13.8% 都是**上界**，假设聚类完美分组、每组都拟合得一样好。
现实中能拿到一半就不错。

### 10.4 还没做但可能有价值的

| 方向 | 说明 |
|---|---|
| **鲁棒估计** | 箱内用修剪均值而非普通均值。⚠️ 但下界必须在**固定像素集**上测，靠剔像素"降低下界"是自欺 |
| **掩膜阈值自适应** | 现在 `0.98 / 0.015 / 90分位` 是在数据集1 上调的。夜景、雪景、棚拍可能全不合适 |
| **感知加权损失** | 现在按像素数加权，等于向最常见颜色倾斜。用 Oklab 雅可比加权能让误差在感知上更均匀 |
| **求解器并行化** | matvec 用 rayon（forward 是 gather，adjoint 是 scatter 需每线程缓冲再归约）。8 核估计快 2-3 倍 |

## 11. 验证

**数值核心**（`cargo test --release`，秒级）：

| 测试 | 判据 |
|---|---|
| CIEDE2000 | 对 Sharma 等的 34 对参考值，偏差 < 1e-4 |
| 传递函数 | 与 Python 逐位一致（< 1e-15） |
| Oklab / CIELAB | 与 Python 偏差 < 1e-12 |
| 四面体索引与权重 | 索引零不匹配，权重偏差 < 1e-15 |
| 恒等 LUT 重构 | 2³/5³/17³/33³ 上误差 < 1e-11 |
| Laplacian | 常量场与线性场严格归零 |
| 中文字体 | 系统字体含 9 个测试字形 |
| 平滑单调性 | 曲率随强度单调下降，端点漂移 < 0.02 |
| 放大视图非平坦 | 灰度标准差 > 3，且变换图里无硬边 |
| 天空渐变范围 | 亮度跨度 > 0.35 |

**端到端**（`cargo test --release -- --ignored end_to_end`，约 3.5 分钟）：
与 Python 生成的 LUT 比对，两批数据平均节点偏差 0.0008。

**结构判据**：折叠数（`det(J) > 0`）、色带风险（二阶差分换算成输出码级）。
判据是「曲率相当于几个码级」，8bit 与 10bit 都以 **1** 为界。

> 位深越高能分辨的曲率越细，所以同一个 LUT 在 10bit 下读数更大。
> 这不代表 10bit 更容易出色带——10bit 的色阶本身还小 4 倍。
> 「1 个码级」这个阈值是启发式，不是行业标准。

**过拟合检验**：5 折交叉验证，训练 ΔE 1.221 / 留出 1.332，
差 **+0.111**（标准误 0.209，t=0.53，不显著）。没有可检测的过拟合。

---

## 12. 一句话总结

> **因为四面体插值对格点值线性，全局色彩映射的拟合就是一个稀疏线性最小二乘问题。
> 剩下的全部工作，是在没有数据的地方、在有约束的地方、在会产生伪影的地方，
> 把这个解"摁"成一个能交付的 LUT。**
>
> **而在当前的模型类里，它已经接近天花板了——想再上一个台阶，必须改变模型本身。**
